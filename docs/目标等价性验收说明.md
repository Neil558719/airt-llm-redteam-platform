# 统一 Chatflow 目标等价性验收

## 用途

用于迁移完成后比较旧客服应用与统一 Chatflow 的同一批共享用例结果。比较器按 `case_id` 对齐，检查：

- 回答关键 token 重叠度；
- passed/failed/error 状态是否一致；
- 工具调用集合是否一致；
- 两边延迟数据是否保留，供报告查看。

它不会把两个不同应用的答案强行要求逐字相同，也不会把安全目标和业务质量目标混在一起。

## 运行

先分别对旧目标和统一 Chatflow 使用同一份共享用例运行，确保输出均为 `evaluation-result-v1` JSONL：

```powershell
.\.venv\Scripts\airt.exe aggregate-report --results runs/legacy/results.jsonl --out reports/legacy
.\.venv\Scripts\airt.exe aggregate-report --results runs/unified/results.jsonl --out reports/assess
```

再执行对比：

```powershell
.\.venv\Scripts\python.exe scripts/compare_results.py `
  --baseline runs/legacy/results.jsonl `
  --candidate runs/unified/results.jsonl `
  --out reports/equivalence `
  --min-answer-overlap 0.4
```

输出：

```text
reports/equivalence/comparison.json
reports/equivalence/comparison.html
```

退出码为 `0` 表示通过；退出码为 `1` 表示存在缺失用例、回答重叠度不足、状态不一致或工具调用不一致。

统一 Chatflow 已完成真正的 Knowledge Retrieval + DeepSeek LLM 节点接入，检索结果来自共享数据集 `08b444c6-168c-43fd-82f2-85477e8298ae`，并能在 Dify workflow 事件中看到 `retriever_from=workflow`。

将共享期望答案改为知识库当前事实后重新验收，结果仍为 FAIL：

```text
reports/equivalence-20260823-kb-truth/comparison.json
```

原因是旧纯文本应用对同一问题返回了与当前知识库不一致的 7 天/运费承担方答案，而统一 Chatflow 按知识库回答 14 天或资料未明确。这证明旧应用不是统一 Chatflow 的可靠行为基线，不能直接以旧模型回答作为迁移正确性标准。

当前建议：保留旧应用作为回归对照，但以知识库事实 + 统一 Chatflow 的检索结果作为新的业务正确性基线；后续对旧应用做一次质量缺陷记录，而不是为了通过等价性而让统一 Chatflow 复现旧回答。
