# 统一运行手册

更新时间：2026-08-23

## 1. 当前架构

当前主目标是原有的 Dify Chatflow 应用：

```text
AI安全测试客服机器人-Agent
UUID: 4f4c8b23-f74d-4c65-82b6-b5ae08c95d32
```

本次合并没有新建 Chatflow，而是在原应用上完成了工作流和测试平台改造：

- Chatflow 保留知识库检索，并接入 DeepSeek LLM 客服回答；
- 普通业务请求走 `knowledge_retrieval → customer_llm → customer_answer`；
- 明确查询虚构订单时授权调用 `query_order`；
- `send_notice` 作为受限工具保留用于安全测试，但默认不可达；
- Dify SSE 适配器支持 Chatflow 的 `workflow_finished.data.outputs`、原生 `node_type=tool`、工具参数/结果和 `retriever_resources`；
- 用户可见回答会移除 `<think>...</think>` 推理块；
- 旧 Dify/FastGPT 应用保留为 deprecated 回归对照或扩展能力，暂不删除。

## 3. 环境变量配置

### 3.1 当前 PowerShell 会话

不要把真实 Key 写入 YAML、Markdown、Git 或命令输出。先在当前 PowerShell 设置：

```powershell
# 统一 Chatflow 应用（chatflow 命令需要）
$env:DIFY_AGENT_API_KEY = "<统一Chatflow应用Key>"

# 独立 Judge（security/quality/release/assess 都会使用）
$env:JUDGE_BASE_URL = "https://<judge-gateway>/v1"
$env:JUDGE_API_KEY = "<独立Judge Key>"
$env:JUDGE_MODEL = "<Judge模型名>"
```

当前默认地址：

- `config.dify.yaml`：`http://localhost/v1`；
- `config.dify.agent.yaml`：`http://127.0.0.1/v1`。

如果 Dify 不在本机，修改对应 YAML 的 `target.base_url`。

### 3.2 让新终端自动继承配置

在已经确认变量正确的 PowerShell 中执行一次：

```powershell
[Environment]::SetEnvironmentVariable("DIFY_AGENT_API_KEY", $env:DIFY_AGENT_API_KEY, "User")
[Environment]::SetEnvironmentVariable("JUDGE_BASE_URL", $env:JUDGE_BASE_URL, "User")
[Environment]::SetEnvironmentVariable("JUDGE_API_KEY", $env:JUDGE_API_KEY, "User")
[Environment]::SetEnvironmentVariable("JUDGE_MODEL", $env:JUDGE_MODEL, "User")
```

执行后重新打开 PowerShell。当前已经打开的终端不会自动刷新 User 环境变量。

只检查是否存在，不输出 Key：

```powershell
Get-ChildItem Env:DIFY_AGENT_API_KEY,Env:JUDGE_BASE_URL,Env:JUDGE_API_KEY,Env:JUDGE_MODEL |
  ForEach-Object { "$($_.Name): " + $(if ($_.Value) { "已设置" } else { "未设置" }) }
```

## 5. Judge 开关与当前运行档位

当前只保留三个底层运行档位和一个组合命令：

| 模式/命令 | 安全 Judge | 质量 Judge | 适用场景 |
|---|---|---|---|
| `security` | 始终调用（可临时关闭） | 不运行质量评测 | Chatflow 工具安全验收 |
| `quality` | 按用例调用 | 实时调用 | Chatflow 知识库质量评测 |
| `release` | 按用例调用 | 实时调用 | 发布前质量、延迟和安全门禁 |
| `chatflow assess` | 始终调用 | 实时调用 | 一次执行安全 + 质量，推荐日常使用 |

`rules` 和 `balanced` 已删除，不再是可用的 YAML 档位；旧的 `airt text ...` 纯文本兼容命令也已删除。当前项目主目标是统一 Chatflow。

### 5.1 当前推荐命令

```powershell
# Chatflow 工具安全，默认调用安全 Judge
.\.venv\Scripts\airt.exe chatflow security

# Chatflow 安全 + 质量，一键执行
.\.venv\Scripts\airt.exe chatflow assess

# 仅质量评测
.\.venv\Scripts\airt.exe chatflow quality

# 发布前门禁
.\.venv\Scripts\airt.exe chatflow release
```

### 5.2 底层 YAML 运行命令

需要精确控制配置、用例和输出目录时，使用 `run`：

```powershell
# security：安全 Judge 始终调用，质量离线
.\.venv\Scripts\airt.exe run `
  --config config.dify.agent.yaml `
  --cases shared_cases/unified_chatflow.yaml `
  --out runs/chatflow-security `
  --mode security `
  --shared-cases

# quality：安全按用例调用，质量实时 Judge
.\.venv\Scripts\airt.exe run `
  --config config.dify.agent.yaml `
  --cases shared_cases/unified_chatflow.yaml `
  --out runs/chatflow-quality `
  --mode quality `
  --shared-quality

# release：实时质量 Judge + 发布门禁
.\.venv\Scripts\airt.exe run `
  --config config.dify.agent.yaml `
  --cases shared_cases/unified_chatflow.yaml `
  --out runs/chatflow-release `
  --mode release `
  --shared-quality
```

如需临时关闭安全 Judge：

```powershell
.\.venv\Scripts\airt.exe chatflow security --security-judge off
```

命令行参数优先于 YAML。`--security-judge off` 只关闭安全 Judge；质量命令仍然使用实时质量 Judge。`chatflow assess` 会分别保存安全、质量原始结果，并额外生成完整综合报告到 `reports/assess/`；综合报告也会写入 `reports/assess/archive/`。

## 11. CI

工作流：`.github/workflows/airt-quality-security.yml`。

Jobs：

- `offline`：Airt 全量测试和迁移静态检查；
- `shared-quality`：共享 YAML 的 pytest 质量回归；
- `live-chatflow-security`：实时 Chatflow 文本安全 + Judge；
- `live-chatflow-image-smoke`：独立运行图片输入安全冒烟测试；
- `live-chatflow-audio-smoke`：独立运行音频输入安全冒烟测试；
- `live-chatflow-quality`：实时 Chatflow 质量 + Judge；
- `unified-gate`：始终汇总全部前置 Job 和结果文件；任一 Job 失败、结果缺失或门禁阈值违反都会失败。

三个安全 Job 彼此独立，文本安全失败不会阻止图片或音频测试执行。每个安全 Job 首次失败后会自动使用 `--resume` 续跑一次，只重试未完成用例；同一 `case_id` 的最后一次尝试决定报告和门禁结果，原始 JSONL 仍保留全部尝试用于审计。第二次仍失败时不会降级为通过。

功能分支只通过 `pull_request` 事件运行一套流水线，避免同一提交重复占用本机 Runner；合并到 `main` 后仍由 `push` 事件自动执行完整发布门禁。文本/质量请求继续使用 20 秒延迟阈值，图片、音频等多模态请求使用独立的 60 秒阈值。

GitHub Secrets：

```text
DIFY_AGENT_API_KEY
JUDGE_BASE_URL
JUDGE_API_KEY
JUDGE_MODEL
```

缺少实时 Secrets 时，实时 Job 和 unified gate 会跳过，不会被误判为安全通过。

## 12. 配置检查与故障排查

```powershell
# 本地运行前检查：配置、Key、用例格式（默认不访问 Dify/Judge）
.\.venv\Scripts\airt.exe doctor --config config.dify.agent.yaml --mode quality --cases shared_cases/unified_chatflow.yaml

# 可选：额外探测 Dify/Judge 地址是否可达，不会执行测试用例
.\.venv\Scripts\airt.exe doctor --config config.dify.agent.yaml --mode quality --cases shared_cases/unified_chatflow.yaml --check-network

# 查看已注册目标，不读取 Key
.\.venv\Scripts\airt.exe targets --registry targets.example.yaml

# 查看命令帮助
.\.venv\Scripts\airt.exe chatflow --help
.\.venv\Scripts\airt.exe chatflow assess --help
```

常见问题：

- `doctor` 默认离线运行；只有显式增加 `--check-network` 才会对配置中的目标和 Judge 地址发起轻量 GET 探测；HTTP 404/401 也表示地址可达，真正的鉴权和业务调用仍由正式测试验证；

- 新终端读不到 `$env:`：执行第 3.2 节的 User 环境变量持久化命令后重新打开终端；
- Judge HTTP 503：检查 Judge 网关可用性后重跑，HTTP 503 会记录为执行异常，不会自动判定通过；
- `unknown target profile`：直接使用 `config.dify.agent.yaml` 的 Chatflow 默认 target，不需要额外指定 profile；
- 质量幻觉率异常：确认使用当前版本适配器，Dify `retriever_resources` 必须进入 `Reply.sources`；
- Chatflow 工具调用失败：确认本机无害工具服务已启动，并检查 `dify_agent_tools/echo_server.py` 的 18080 端口。

本地工具服务启动：

```powershell
Start-Process -FilePath ".\.venv\Scripts\python.exe" `
  -ArgumentList "dify_agent_tools\\echo_server.py 18080" `
  -WindowStyle Hidden
Invoke-RestMethod http://127.0.0.1:18080/health
```

## 13. 离线回归基线

基线比较只读取本地 JSONL，不创建 API 客户端，也不会调用 Dify 或 Judge。建议在一次确认通过的 Chatflow 质量或安全运行后保存基线：

```powershell
.\.venv\Scripts\airt.exe baseline save `
  --results runs/chatflow-quality/results.jsonl `
  --out baselines/chatflow-quality.jsonl
```

后续运行完成后，日常推荐直接比较最近一次 `assess`：

```powershell
.\.venv\Scripts\airt.exe baseline compare-assess `
  --baseline baselines/chatflow-assess.jsonl
```

命令会自动读取 `runs/chatflow-assess/security/results.jsonl` 和 `runs/chatflow-assess/quality/results.jsonl` 并合并比较；指定历史运行时增加 `--run-dir runs/chatflow-assess-20260825`。无需手动查找或合并 JSONL。

默认检查回答相似度不低于 `0.4`、用例状态不变化、工具调用集合不变化。可选参数：

- `--min-answer-overlap 0.6`：提高回答相似度要求；
- `--max-latency-increase 0.5`：限制候选结果延迟最多比基线增加 50%。

比较结果输出到 `reports/baseline-assess/<时间戳>/comparison.json` 和 `comparison.html`；存在回归时返回退出码 `1`，适合接入本地脚本或发布前检查。需要比较任意两份 JSONL 时，仍可使用高级命令 `baseline compare`。

## 14. 企业常见安全用例

统一 Chatflow 用例集当前包含 26 条用例，覆盖多轮提示注入、间接提示注入、敏感信息泄露、会话隔离、跨用户越权查询、知识库权限绕过、知识库版本污染、工具参数篡改、工具失败伪成功、重复副作用、高风险工具误调用、工具循环请求、SSRF/内网访问、输出 HTML 注入、资源消耗、中英文混合攻击，以及图片和音频伪指令注入。新增用例仍保存在 `shared_cases/unified_chatflow.yaml`，Airt 与 pytest 继续读取同一份数据；运行 `cases validate` 可在联网前发现格式、重复 ID 和字段错误。

多模态用例使用 `input.type`（`image`、`audio`、`video`、`document`）和 `input.asset` 描述输入资产。当前 Dify 适配器支持远程 URL 文件描述；本地文件上传和 OCR/语音转写需要目标 Chatflow 开启文件上传及对应模型节点后再接入。

用例结构约定如下：

```yaml
- case_id: 稳定唯一 ID
  category: security 或 tools
  question: 首轮测试请求
  turns: [可选的多轮请求]
  security:
    judge_goal: 攻击成功判定标准
    refusal_required: 是否要求拒答
  tools:
    expected: 允许/预期工具
    forbidden: 禁止工具
    argument_any: 参数或工具结果中必须观测的值
```

### 多模态安全测试

单文件测试现在无需单独启动 HTTP 文件服务。使用 `--asset` 指定项目中的图片或音频文件，平台会自动匹配用例、启动临时文件服务并在测试结束后关闭：

```powershell
.\.venv\Scripts\airt.exe chatflow security `
  --config config.dify.agent.yaml `
  --asset fixtures\multimodal\prompt_injection.png `
  --security-judge always
```

```powershell
.\.venv\Scripts\airt.exe chatflow security `
  --config config.dify.agent.yaml `
  --asset fixtures\multimodal\prompt_injection.wav `
  --security-judge always
```

文件名包含 `sensitive`、`tool`、`ocr` 或 `mixed` 时会自动优先选择对应场景；也可以显式指定 `--asset-type image` 或 `--asset-type audio`。

多模态样例文件为 `shared_cases/multimodal_chatflow.yaml`，当前包含 7 条图片/语音安全用例。用例中的 `input.asset` 支持可被 Dify 访问的远程 URL；如使用本地文件，需要先通过 Dify 控制台上传，或将测试资产放到可访问的静态地址后替换 YAML 中的路径。


```powershell
  --config config.dify.agent.yaml `
```
