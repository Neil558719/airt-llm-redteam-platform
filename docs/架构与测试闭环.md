# 架构与测试闭环

## 项目定位

本项目是面向 Dify Chatflow/Agent 应用的 LLM 安全与质量自动化测试平台。它把共享测试用例、目标适配器、独立 Judge、工具观测、结构化报告和 CI 发布门禁串成一条可复现的测试链路。

## 数据流

```text
共享 YAML 用例
      ↓
离线 Schema 校验 ──────→ CI 早期失败
      ↓
目标适配器（Dify Chatflow / FastGPT 扩展）
      ↓
规范化 Reply（回答、来源、工具调用、延迟）
      ├────────→ 安全规则 / 安全 Judge
      └────────→ 质量指标 / 质量 Judge
                      ↓
              evaluation-result-v1 JSONL
                      ↓
       HTML / JSON 详细报告 + 历史 archive
                      ↓
           趋势报告 / 静态 Dashboard
                      ↓
              release 门禁与 CI artifact
```

## 当前闭环能力

- `airt cases validate`：运行前校验共享用例或标准 AttackCase YAML；不调用外部服务。
- `airt chatflow security`：执行安全与工具边界测试。
- `airt chatflow quality`：执行知识库回答质量评测。
- `airt chatflow assess`：合并安全和质量结果，写入 `reports/assess`。
- `airt chatflow release`：执行发布门禁，检查安全分、质量分和延迟。
- `airt trend`：从最新报告和历史 archive 离线生成趋势。
- `airt dashboard`：生成可直接上传 CI 的静态总览页。

## 面试展示建议

演示时可以依次展示：

1. 用例 YAML 和 `airt cases validate` 输出；
2. Chatflow 工具调用观测及安全报告中的请求、回答、判定依据；
3. 质量报告中的正确性、相关性、完整性、忠实性和 Judge 理由；
4. `reports/assess/archive/` 的历史归档；
5. `trend.html` 和 `dashboard.html`；
6. GitHub Actions 的测试、门禁和 artifact。

所有示例均应使用虚构订单和脱敏文本，不要把 API Key、Authorization 或生产数据写入报告。
